# 语境中的排版检查

用于把对字体与版面的学习转化成一次具体的页面检查。来源与理解见 [Apple 排版学习笔记](../learnings/2026-10-17-apple-typography.md)；作者已有可参考的 [Chinese Web Typography skill](https://github.com/Skywt2003/chinese-web-typography)，是否集成由实际任务决定。

## 取得可比较的页面

明确语言地区、真实文案、核心阅读任务、目标设备和当前设计意图。查看实际字体、回退字体和容器约束，区分固定短标题、流动正文、控件与用户内容。保留相同内容的基线，便于判断修改带来的效果。

## 根据观察定位问题

| 检查面向 | 在真实页面上提出的问题 |
| --- | --- |
| 字体与混排 | 中文、西文、数字及特殊符号在视觉大小、重量和基线上是否协调？回退后是否仍可读？ |
| 留白与标点 | 间距是否帮助辨认语义？所选处理是否符合该语言地区与内容用途？ |
| 行末与换行 | 实际行末是否影响理解或构成突兀短行？局部调整会不会使其他宽度更差？ |
| 标题与层级 | 标题的阅读顺序、语义分组与视觉重心是否清楚？ |
| 窄屏与放大 | 更窄的容器、长名称或放大文字时，有无溢出、遮挡和内容遗漏？ |

这些问题用于引导检查，不要求每个页面都修改全部项目。品牌偏好与阅读缺陷应分别说明。

## 选择实现再复查

优先处理已观察到的问题，比较相同文案和宽度下的结果。需要 CSS、库或字体功能时，查目标环境适用的官方资料，按需采用；避免同时引入多种处理方式，使变化原因无法判断。

字体或内容变化后，重新查看受影响的行与标题。固定文案的局部编排应有维护依据；动态内容需要容忍长度与语言变化。科研或数据页面还需查看关键符号和数字是否完整可读。

## 交付检查记录

简要说明改了哪里、为什么、在什么环境与宽度实际看过，附可比较的结果或问题位置。无法运行浏览器时，只报告源码层面检查，把视觉结果列为待验证。

本 workflow 尚未在真实页面上试用；它不包含对某个项目已经改善的声明。
