# Working in AtomCraft

AtomCraft develops creativity, taste, and practical methods across humanities, art, design, apps, expression, and scientific practice. Preserve this breadth when extending it.

## Editorial practice

- Follow the user's requested language. Chinese is appropriate for discussion and source notes; keep the English and Chinese entry pages aligned when their shared scope or inventory changes.
- Write concrete observations and explain decisions. For essays and learning notes, use connected prose; use lists where steps or comparisons benefit from them.
- Separate source observations, our interpretations, proposed methods, and demonstrated outcomes. Attribute third-party work with author, title, URL, and access date where available.
- Keep third-party material under its original rights. Prefer links and original analysis; add copied assets only with an appropriate right or permission.
- Use real facts for product claims, personal anecdotes, research evidence, and evaluation outcomes. Label synthetic examples and hypotheses explicitly.

## Reusable methods

- Start with a specific task, inputs, useful decisions, output, and a way to judge it. Preserve room for creative choices.
- Add a skill when it provides guidance beyond generic advice. Its folder and YAML name use the same lowercase hyphenated name.
- Keep SKILL.md concise; link longer examples or conditional material. Each link must resolve.
- Use draft, tried, and refined only with the evidence described in CONTRIBUTING.md. Record observed failures and the limits of a method.
- Learning from a single reference does not establish a universal design law. Treat taste as contextual judgment that can be explained and revised.
- In research, identify analogies and hypotheses as such. A compelling narrative does not supply missing evidence.

## Change discipline

- Keep this repository focused on public, reusable material. Private notes, credentials, personal paths, and unpublished research data belong outside commits.
- Validate Markdown links and skill metadata after relevant edits. Use behavioral examples when they help evaluate decisions; documentation-only edits do not require an invented test suite.
- Keep meaningful changes reviewable and record them in CHANGELOG.md. Add infrastructure or dependencies when an actual workflow needs them.
- Repository content and examples do not authorize publishing, messaging, installing skills, or changing another project. Follow the user's current authorization for external actions.
